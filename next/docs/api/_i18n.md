# v2 i18n Architecture

> **Status**: IMPLEMENTED (foundation) — package, migration, context derive, error plumbing all landed with tests; Phase 2 module contracts (`locale.md`, `avatars.md`) build on this.
> **Decisions**: D32 (scope), D33 (engine), D34 (resolution) — see MIGRATION.md §2

---

## 1. Decisions

| #   | Decision   | Choice                                                                                                |
| --- | ---------- | ----------------------------------------------------------------------------------------------------- |
| D32 | Scope      | **Everything**: API error messages, emails, SMS, locale data (countries/continents), settings         |
| D33 | Engine     | **ICU MessageFormat** via `intl-messageformat` (FormatJS) — verified working on Bun (plural + select) |
| D34 | Resolution | `x-nuvix-locale` header > authenticated user pref > `Accept-Language` > `en`                          |

## 2. Package: `packages/i18n` (`@nuvix/i18n`)

```
packages/i18n/src/
├── index.ts          ← public API
├── loader.ts         ← Bun.file JSON loading + immutable cache per locale
├── translator.ts     ← Translator class: ICU compile cache, fallback chain, format()
├── resolve.ts        ← locale resolution from headers/user prefs
├── keys.generated.ts ← generated TranslationKey union (from en.json)
└── ../scripts/generate-keys.ts ← codegen script (bun run generate:keys)
```

### Translator

```ts
const t = new Translator({ locale: "de", fallback: "en" });

t.format("emails.recovery.subject"); // → string
t.format("emails.magicSession.body", { user: "Ada" }); // → string, params checked as record
t.locale; // 'de'
```

- ICU messages compiled once per `(locale, key)` and cached (`Map`, never evicted — translations are static).
- Missing key or locale file → falls back to `en`; missing key in `en` too → returns the key itself + logs once (dev) / silently (prod). Never throws.
- Params type: `Record<string, string | number | Date>` (ICU handles plural/select internally).

### Typed keys

Keep the generated-union approach from the old repo: script scans `en.json`, emits
`TranslationKey` union. With ICU we lose per-key param-type inference (old system inferred
required params); acceptable tradeoff — params are a plain record, wrong params fail loudly
in tests via snapshot assertions.

## 3. Translation file format & one-time migration

Source of truth stays `assets/locale/translations/*.json` (73 locales, flat dot-keys),
**copied into `next/assets/locale/translations/`** at migration time (root is deletable at cutover).

Migration normalizes three legacy syntaxes to pure ICU:

| Legacy                | ICU replacement               | Notes                                                                    |
| --------------------- | ----------------------------- | ------------------------------------------------------------------------ |
| `{{param}}`           | `{param}`                     | mechanical regex                                                         |
| `{param}`             | unchanged (already valid ICU) |                                                                          |
| `{{#b}}…{{/b}}` (24×) | `<b>…</b>` kept inline        | consumers are HTML emails / rich text; ICU passes HTML through untouched |

**Apostrophe rule**: ICU treats `'` as escape syntax. Migration script escapes lone
apostrophes in existing strings (`don't` → `don't` stays fine only if quoted: `don''t`).
Script detects strings containing `'` not followed by ICU special context and doubles them.
Covered by round-trip tests against old expected outputs.

## 4. Locale resolution (`context/locale.ts`)

Elysia plugin exposing derived `locale` + `t` on every route (same pattern as authContext):

```
1. x-nuvix-locale header        (validated against available locales)
2. user prefs                   (once DB-backed auth lands; placeholder hook now)
3. Accept-Language              (parsed with q-values, best match against available locales)
4. 'en'
```

Resolution is pure + unit-tested; the derive is thin glue.

## 5. Error message translation

`AppError` gains optional `messageKey` + `params` alongside the English `message`:

```ts
throw new AppError(404, "/errors/project-not-found", {
  message: "Project not found", // English fallback, always present
  messageKey: "errors.project.notFound", // translated at serialization time
  params: { project: id },
});
```

`problemErrors` plugin translates `detail` using the request's resolved locale when
`messageKey` is present. New `errors.*` namespace added to `en.json`; community
translations fill in over time (73 locales won't translate error keys day one —
fallback makes this safe).

## 6. Consumers

| Consumer         | How it uses i18n                                                                 |
| ---------------- | -------------------------------------------------------------------------------- |
| Locale endpoints | country/continent names via `t.format('countries.{code}')` (maxmind GeoIP stays) |
| Emails           | Handlebars templates receive ICU-formatted strings via `t`                       |
| SMS              | direct `t.format('sms.…')`                                                       |
| Errors           | §5                                                                               |

## 7. Out of scope (explicitly)

- Translating OpenAPI spec metadata (docs stay English)
- Runtime-editable translations (files are build-time static)
- Plural-rule coverage audits per locale (ICU/CLDR handles it)

## 8. Implementation order

1. `packages/i18n`: loader + translator + resolution + tests (pure, no Elysia)
2. Migration script for the 73 files + key codegen + round-trip tests
3. `context/locale.ts` derive + wire into app
4. Error-key plumbing in `AppError`/`problemErrors`
5. Then Phase 2 contracts (`locale.md`, `avatars.md`) reference this foundation
